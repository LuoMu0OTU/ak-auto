## 0. 一页结论：本阶段到底要改变什么？

现有项目**已经有真实 GUI**。根目录的 `.bat` 并不对应每个业务功能：`首次安装.bat` 用于初始化，`启动界面.bat` 打开 GUI，`启动日常.bat` 和 `静默日常.bat` 是快捷运行入口；打包后的 `arknights-auto.exe` 也可直接打开 GUI。

问题不是“没有界面”，而是**统一界面尚未成为成熟、完整、易懂的用户操作中心**：当前任务中心主要是任务复选框、预设按钮和开始执行；具体配置散落在“设置 / 高级设置”等区域，部分未完成能力仍以可填写参数的形式出现；视觉层次、交互反馈、首次使用体验也还需要产品化审查。

本阶段要做的是：

1. **唯一推荐入口：** 普通玩家用 `arknights-auto.exe` 打开统一控制面板，不需要寻找多个 `.bat` 或学习 CLI。
2. **功能集中：** 公招、刷图、基建、信用商店、好友访问、任务/邮件/签到等在**同一应用窗口**内能找到对应的任务卡片、配置入口、状态与帮助。
3. **简单/高级共存：** 简单模式预设驱动、低认知负担；高级模式可逐项配置参数和任务顺序。两者共享执行核心、配置及任务 ID，不能分叉。
4. **真实功能优先：** 没做完的“自动选关”“多次连战滚动选择”“基建干员换班”等明确写“未完成/待验证”，不能渲染成已可用按钮。
5. **可靠可维护：** GUI 不直接点击游戏；后台线程执行耗时操作，事件与状态清晰；保留 CLI、`.bat` 快捷入口与现有配置兼容。

**非目标：** 本期不重写 MaaFramework 流水线、不更换 GUI 技术栈、不重新造第二套任务引擎、不凭空承诺全部游戏功能、不为了“漂亮”牺牲可靠性、不实现未获批的自动选关/换班/无限自动循环。

## 2. 目标产品形态与信息架构

### 2.1 一体化控制面板（一个窗口、多页面，不是多个 exe/bat）

建议总体布局：

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ arknights-auto     游戏连接 / 资源状态     当前任务状态      [模式切换] │
├────────────────┬────────────────────────────────────────────────────────┤
│ 首页 / 概览    │  当前页面内容                                           │
│ 任务中心       │                                                        │
│ 运行记录       │  简单模式：任务卡片、预设、开始/停止、状态与结果         │
│ 设置           │  高级模式：更多任务配置、排序、诊断、策略与高级参数       │
│ （高级入口）   │                                                        │
│ 诊断           │                                                        │
├────────────────┴────────────────────────────────────────────────────────┤
│ 状态栏：运行中任务 / 进度 / 关键警告 / 安全停止入口                      │
└─────────────────────────────────────────────────────────────────────────┘
```

> **只是信息架构草图，不是 UI 实现效果图。** 可在首次审计后调整布局，但要保留“统一入口、明显状态、低学习成本”的目标。

建议页面与用途：

| 页面/区域 | 简单模式 | 高级模式 |
|---|---|---|
| 首页 / 仪表盘 | 游戏与资源就绪状态、推荐预设、一键运行/停止、最近结果 | 增加详细运行状态、错误原因与诊断入口 |
| 任务中心（核心页面） | 按分类展示任务卡片；勾选、预设、任务说明、执行顺序摘要 | 各任务展开完整策略配置、排序和风险提示 |
| 刷图卡片/详情 | 关卡限制、次数、理智提示；不支持的选关能力明确说明 | 理智下限、重试与安全边界，展示已验证范围 |
| 公招卡片/详情 | 启用/禁用、推荐配置说明 | 标签优先级、次数、时长、保底、加急策略 |
| 基建卡片/详情 | 收菜/线索/恢复生产的真实能力说明 | 细项与风险说明；自动换班未实现则禁用 |
| 信用商店卡片/详情 | 自动采购开关与基本说明 | 商品优先级、黑名单等真实已接入参数 |
| 运行记录 | 最近执行、成功/失败与耗时 | 详情、分步骤日志、错误信息、诊断包导出 |
| 设置 / 环境 | 游戏路径、窗口/资源检查、首启向导 | 配置方案、详细运行参数、更新检查开关 |
| 诊断（高级入口） | 简明错误指引可从失败状态直达 | 环境自检、失败截图、脱敏诊断导出 |

**重要：** “页面/详情”不要求每项拆独立导航页。优先使用同一个“任务中心”里的**分组卡片 + 展开详情 / 右侧设置区域**，避免导航膨胀及多个独立窗口。

### 2.2 统一任务卡片规范

每张任务卡片至少应有：

- 任务名称、用途及简短说明、开关（或复选框）。
- 当前支持状态：`可使用 / 有限制 / 待验证 / 未实现`，须从**单一事实来源**映射到 UI；不能随意手写与代码脱节的标签。
- 简单模式的推荐策略与一目了然的执行效果。
- 高级模式可展开设置，含范围限制、默认值、风险提示和“保存后生效”反馈。
- 明确的错误/不支持状态；禁用功能写明原因、关联待办或替代方法。
- 不能将“配置字段存在”误报为“功能已实现”。

**支持状态判定规则：**

1. `已实现`：代码存在且能够到达相应执行路径。
2. `已测试`：有明确的自动化测试或手动验证记录；标明验证类型。
3. `已验证可用`：有具体支持环境下的真实游戏/真实用户完成记录。
4. `有限制`：能用但有分辨率、场景或次数边界。
5. `计划中/未实现`：不可通过启用按钮诱导用户误用；必要时只展示说明。

状态矩阵由功能负责人审查，GUI 不可自行推断成功率、误用单个案例宣布“稳定”。

## 3. 交互与视觉质量标准

### 3.1 设计原则

- **信息优先级：** 游戏是否连接 → 资源是否就绪 → 选择任务 → 配置 → 开始/停止 → 结果，视觉顺序必须明确。
- **统一而非拼凑：** 暗色主题延续现有设计，集中定义颜色、字号、间距、圆角、边框、控件尺寸与状态色；不要每页单独写一套 QSS。
- **中文优先：** 减少裸露的 `StartUp/Fight/Infrast` 等内部 ID；可在高级详情中展示。
- **视觉克制：** 不追求动画数量；避免大面积无意义空白、密集文本、对比度不足或花哨装饰。
- **响应式桌面布局：** 1024×680 为当前默认窗口尺寸，至少测试 100%/125%/150% DPI；内容空间不足时可滚动，不能遮挡关键按钮。
- **无侵入：** 参考成熟桌面软件的信息组织，不能直接复制第三方界面图、图标或受保护素材。
- **状态一致：** 运行中、完成、失败、取消、资源缺失、断开连接、更新可用、空记录均有明确反馈。

### 3.2 核心流程的预期体验

**新用户：** 启动 exe → 首次向导 → 看懂游戏/识别资源状态 → 选择“每日常规”预设 → 一键运行 → 看见运行进度与结果。无需修改 JSON 或打开终端。

**进阶用户：** 切换高级模式 → 在任务卡片展开各功能设置 → 调整任务顺序、保存预设 → 运行 → 到运行记录查失败原因 → 必要时导出诊断包。

**遇到失败：** 页面告知“什么失败 / 是否影响后续任务 / 建议下一步”，允许进入详情，但不能弹一个无意义的 Python 堆栈让用户自己猜。

**运行中停止：** 停止按钮始终可见；提示处于安全停止中，最终进入 `Cancelled` 等明确终态，且不遗留失控的游戏点击线程。

## 4. 约束：保证 GUI 改造不会破坏自动化核心

1. **统一业务内核。** 只允许 GUI → Application Service / ExecutionController → 任务目录 / MaaFramework；GUI 不得直接调用截图、OCR 或点击游戏。
2. **保留现有 CLI / bat。** `首次安装.bat`、`启动界面.bat`、`启动日常.bat`、`静默日常.bat` 保留兼容；普通用户首推 exe，不以“删除脚本”伪装完成 GUI 改造。
3. **配置唯一。** 简单/高级模式读取同一版本化配置；隐藏高级参数时不得重置，模式切换不得创建第二份互相冲突的任务配置。
4. **线程安全。** 游戏任务、资源下载、联网更新检查、诊断导出等耗时工作不得阻塞 GUI 主线程；信号跨线程更新界面。
5. **任务单例。** 同一时间只允许一个游戏输入控制者；重复点击开始、切换页面或关闭窗口不得启动并行点击线程。
6. **安全默认。** 吃药、碎石和其他付费/稀缺资源消耗默认关闭；风险操作必须显式授权与可理解的提示。
7. **明确不支持。** 当前 `fight.stage` 自动导航未完成；`times > 1` 及可视区外滚动需要专项验证；基建换班未完成；不要在 UI 中偷偷开放未经验证的路径。
8. **可诊断。** 运行记录保留 run_id / task_id / 结果 / 时间等信息，支持错误原因定位；日志、截图、诊断包需要审查敏感信息。
9. **可升级。** 不破坏老配置，不改变已发布 CLI 语义；若涉及配置迁移，必须提供回滚/备份及测试。
10. **最高规范。** 遵守仓库已有 `AGENTS.md`。本计划**不得取代、覆盖或绕过**既有长期规范；产生冲突时先报告负责人。

## 5. 分阶段落地计划（每一步单独验收）

### G7.0｜GUI 现状审计与原型确认（**先做，不直接重构**）

**工作：**

- 清点 GUI 的页面、控件、信号、真实执行入口、配置来源、文案与错配项。
- 形成任务与配置矩阵：`可用任务 → 简单模式可见内容 → 高级可配参数 → 消费该参数的执行路径 → 测试证据`。
- 使用真实运行窗口截图评估密度、层级、布局、DPI、首次启动路径及文本歧义。
- 提出线框图或静态交互草图，并标注当前功能与计划功能。
- 给出最小侵入的文件拆分建议、测试基线和预计风险。

**交付：** `docs/architecture/PHASE7_GUI_AUDIT.md`、功能事实矩阵、界面草图/截图（必要时）、分步实施清单。

**退出条件：** 负责人确认首页、任务中心与高级模式的交互方向；明确哪些功能不可开放；未确认不开始大规模 GUI 重构。

### G7.1｜统一导航与任务中心改造（P0）

**工作：**

- 保留现有入口，重构主窗口排版与侧栏状态呈现。
- 将任务复选框列表改为**按类别归组的任务卡片**：日常奖励、公招、基建、信用商店、好友访问、刷图等。
- 每卡可勾选/关闭、查看说明、显示状态；高级模式支持展开真实已接入的参数。
- 首页集中展示：游戏/识别资源状态、推荐预设、当前任务、进度与安全停止、最近一次结果。
- 任务选择与执行次序仍调用现有 `TaskPage` / `_sequence` 及共享执行服务，必要时做最小组件拆分。

**退出条件：** 用户不借助 `.bat`/CLI/JSON 能在 GUI 找到全部当前支持任务，并完成勾选、预设、执行与停止；CLI 回归不受影响。

### G7.2｜功能配置集中管理与双模式一致性（P0）

**工作：**

- 将与任务强相关的设置搬到相应卡片的展开区/详情面板，设置页保留全局环境与应用选项。
- 公招：标签优先级等参数只展示已被执行核心消费的项，未验证则注明。
- 信用商店：商品优先级与黑名单集中在采购配置下。
- 刷图：清楚解释“最近一次作战”与“指定关卡导航”的差别；不支持的选关不应表现为已生效；理智与次数安全边界可见。
- 基建：明确已支持收菜、线索、恢复生产，不将其与“干员自动换班”混为一谈。
- 修复旧“计划中”文案；设置项保存反馈明确，失败时显示原因。
- 简单/高级切换保留配置及任务状态；与已有预设、多配置方案逻辑保持一致。

**退出条件：** 在高级模式变更参数 → 保存 → 切到简单模式 → 切回高级模式，参数不丢失；对于标记“可用”的参数可追踪到真实执行路径和测试证据。

### G7.3｜运行反馈、错误处理与视觉打磨（P1）

**工作：**

- 为连接状态、任务加载、运行中、完成、失败、停止与无记录建立统一视觉表现。
- 建立清晰的进度信息层级：任务名（中文）、执行位置、已完成/总任务数、耗时、异常说明。
- 将技术堆栈折叠在“详细信息”，优先显示用户能采取的解决步骤。
- 整理字体、控件状态、间距、卡片样式、滚动及键盘操作；适配高 DPI。
- 诊断包导出前提示可能包含日志与截图，检查脱敏覆盖范围，避免默认公开个人数据。
- 修复多次重复点击、任务运行中页面切换、关闭窗口时可能出现的竞态和状态不一致。

**退出条件：** 真实运行与模拟失败场景里，界面没有假死、误导性成功提示、状态消失或不可见的停止操作；截图评审通过。

### G7.4｜自动化回归、真实用户验收与发布（P0 发布门槛）

**必须覆盖的自动化测试：**

- GUI 页面切换、任务类别/卡片数据、空状态、预设应用和任务执行序列。
- GUI → 共享 Application → 模拟任务（Fake/Mock）的连接，不引入 GUI 内独立执行器。
- 模式切换不丢参数；保存与迁移对旧配置兼容；不支持参数不会假生效。
- 连续点击开始、运行时停止、窗口关闭与异常回调、更新检查失败、资源未就绪。
- 动态控件信号连接、异常/失败态文本、基本可访问性与 offscreen Qt 冒烟。

**必须覆盖的手动真实环境验收：**

- 干净 Windows 10/11 x64 环境（无预装 Python）：解压、双击、首次向导、下载资源、连接游戏、运行一个真实任务、停止与重启。
- 建议窗口尺寸与 DPI：默认 1024×680、100%/125%/150%；核查字体不截断、按钮不重叠、重要状态可见。
- 简单模式从选择预设到完成；高级模式从修改配置到任务消费配置，均留实际日志和截图。
- CLI / 四个原有 bat 不回归；构建前后 exe 文件名、说明文档、下载包一致。
- 消费付费资源默认关闭；窗口识别失败、截图失效、异常弹窗时安全失败。
- CI 测试与构建真实通过；如 `doctor` 是发布阻断条件，不能继续以 `continue-on-error: true` 掩盖失败。

**退出条件：** 有可审核的测试记录、完整安装/GUI 操作截图或录屏、未解决缺陷列表、发布回滚方案；负责人明确批准后再合并/打 tag/发布。没有干净机验收，不得宣称“完全兼容所有 Windows 电脑”。

## 6. 优先级与范围管理

| 优先级 | 本阶段事项 | 原因 |
|---|---|---|
| **P0** | 统一 GUI 入口与真实任务控制中心 | 本阶段主要用户价值 |
| **P0** | 简单/高级使用同一配置与核心、状态正确 | 防止表面好看但功能不生效 |
| **P0** | 未实现/有限制功能显式标记，危险配置受保护 | 防止误导和误操作 |
| **P0** | 安全停止、稳定主线程、CLI/打包回归 | 基础可靠性 |
| **P1** | 现代视觉、清晰状态、错误指引、高 DPI、诊断体验 | 提升真实使用体验 |
| **P1** | 文档状态统一、CI 发布冒烟严格化 | 长期维护性 |
| **P2 / 另立任务** | 指定关卡自动导航、连战超出可视区的选次、干员换班 | 属自动化算法能力，不应混进 GUI 重构制造范围失控 |
| **暂缓** | 插件系统、复杂条件编排、全面换框架、跨平台重写 | 成本高，当前不构成主要价值 |

**推荐节奏：** 先把“统一任务中心 + 配置接线 + 状态准确”做成可用版本；再做视觉打磨与发布验收，而不是先砸时间画皮肤、后面才发现按钮没有真实能力。

## 7. 建议代码组织（允许审计后调整）

现有 Qt Widgets 和 Shared Application 层继续保留。仅在原 `gui/` 内按**实际复杂度**渐进拆分，避免一次性重构所有模块。

```text
src/ak_auto/
├── gui/
│   ├── main_window.py       # 导航、全局运行状态、页面编排
│   ├── theme.py             # 统一设计令牌与 QSS
│   ├── worker.py            # 后台任务与 Qt 信号桥接
│   ├── pages.py             # 旧页面：渐进拆分或保留兼容
│   ├── ...                  # [拟议] task_center / task_cards / dialogs 等
│   └── ...                  # [拟议] viewmodels 或 presenters（确有必要才引入）
├── application/            # 统一执行与配置服务，不复制逻辑
├── domain/                 # 任务目录、参数、状态、结果
├── tasks/                  # 已有 Python Custom Actions
└── ...
```

**架构边界：** GUI 组件接收“任务描述 / 支持状态 / 当前配置 / 运行事件”，调用 Service 执行或保存；不能在按钮回调中实现某项游戏任务的截图与点击流程。

如果需新增功能状态元数据：优先复用已有 `TaskDefinition` 或领域模型，设计一个可测试、可审查的单一来源，避免引入另一份手写 JSON 维护两套状态。

## 8. 质量门禁与评审产物

**每一轮 Agent 汇报必须包含：**

1. 本轮目标与改动范围；具体变更文件。
2. 本轮实际完成 / 仅部分完成 / 尚未实现的事项。
3. 执行过的测试命令、结果、失败项与运行环境；未运行就直说。
4. 实际 GUI 截图（若工具具备，至少首页、任务中心、简单/高级模式、失败状态）；**禁止拿合成图冒充软件运行截图**。
5. 兼容性：CLI、bat、exe、配置迁移是否改变；风险与回滚方式。
6. 下一轮最小任务；是否已达到当前里程碑退出条件。

**严禁：**

- 编造通过的测试、真实游戏成功记录或发行包。
- 以增加 .bat 代替统一 GUI；把批处理脚本当作用户配置界面。
- 删除旧入口或破坏 CLI 兼容，除非负责人明确批准。
- 将计划中功能设计成可点击但不生效的假开关。
- 先跳过安全检查、后期再补；偷偷开启吃药/碎石等资源消耗。
- 未经授权大规模重构、覆盖本地工作、推送、合并 PR 或发布 Release。
- 因上下文压缩丢失 `AGENTS.md`、本计划与当前阶段事实。

### 阶段完成的判定（全部必需）

- [ ] 普通用户不需要任何 `.bat`/CLI/JSON，就能用**一个 exe/窗口**完成主要受支持任务的选择、设置、执行、停止与查看结果。
- [ ] 简单模式与高级模式是同一任务执行核心和配置，不复制运行逻辑、不丢失设置。
- [ ] 已支持、受限制、未实现的任务在 GUI 中表达准确；未实现能力不可误操作。
- [ ] 关键交互有成功/失败/加载/取消等真实状态；错误信息可理解。
- [ ] 所有 GUI 回调无阻塞性耗时操作，任务输入控制互斥与安全停止经测试。
- [ ] 1024×680 默认尺寸及 100%/125%/150% DPI 的主要界面验收通过。
- [ ] 自动化测试、流水线 lint、Windows 构建、打包冒烟与实际环境验证记录可审核。
- [ ] README、BUILD、ROADMAP、STATE、CHANGELOG 与实际状态一致。
- [ ] `AGENTS.md` 仍有效；负责人明确批准合并及对外发布。
